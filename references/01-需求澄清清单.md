# 01 · 需求澄清清单（阶段 0 必读）

> 用法：逐项向用户提问，用选项题降低回答成本。全部关键项有答案后，输出《需求确认表》请用户确认。

## A. 必答项（缺一项都不开工）

| # | 问题 | 为什么必须问 |
|---|---|---|
| A1 | 站点正式名称？（如「卓越大健康」） | 写进标题/导航/页脚/logo 旁文字 |
| A2 | 网站性质？展示型官网 or 需要后台/交易？ | 决定静态站路线是否成立。展示型=静态站最优解 |
| A3 | 一级栏目结构？（给 5~7 个） | 导航和页面骨架。示例：首页/业务板块/医养服务/长者风采/新闻动态/关于我们/合作共赢 |
| A4 | 主色调？（给品牌 logo 或参考站） | 全站换肤基准。如参考站是橙色就定橙色系 |
| A5 | 目标受众是谁？ | 决定文案口吻和内容侧重（如养老行业=长者+家属+政企三方） |
| A6 | 手里有什么素材？（logo/照片/宣传册/公众号文章链接/数据） | 决定哪些板块能落地、哪些要占位 |
| A7 | 行业合规红线？ | 医疗养老：禁绝对化用语、不贬低同行、不夸大疗效、不用"免费"、数据有出处。其他行业问对应监管要求 |
| A8 | 域名买了吗？备案了吗？服务器在哪？ | 决定部署路线和时间预期（未备案=最长 2~4 周路径） |
| A9 | 适配要求？（默认：桌面+平板+手机三端自适应） | 验收标准的一部分 |
| A10 | 本次推进边界？（只规划/只搭建/含部署） | 防止越权操作，尊重"不部署不擅自搭建"类指令 |

## B. 建议问（影响细节质量）

- B1 有没有特别想模仿的同行官网？（有就直接进对标拆解）
- B2 表单需求？（预约/咨询表单要不要收集数据？收集的话接腾讯问卷/金数据等第三方，免后端）
- B3 新闻资讯是站内文章还是跳公众号/外部链接？（跳外链可省掉 CMS）
- B4 有没有一句话品牌 slogan / 核心卖点清单？（如：医保可结算/长护险定点/城央地段/医养结合）
- B5 多机构/多业务线怎么呈现？（各一张卡 or 合并？互相要不要交叉标注？）

## C. 真实问答样例（卓越大健康项目，可作提问话术参考）

- 主色：用户先定"绿色系"，后改"模仿泰康"→ 最终定为**泰康橙主调**（logo 蓝字冲突通过吸顶白底导航化解）
- 表单：选择**先不接后端**（展示用），后续再接腾讯问卷
- 域名备案：**都没有**，走「先出保姆级指引，公司去办」路线
- 业务板块：5 张卡保留，但宽逸颐养院↔小港中医医院**物理同址绑定**，卡片互相标注"同一地址"
- 素材边界：用户确认"数据和图片暂时就这么多"→ 缺口板块用【待替换真实素材】占位，禁止编造
